# Slice 1 Implementation Plan

> Execute inline using the established implementation/testing workflow. User explicitly requested the next fixed slice; no additional design approval is needed. Work in branch codex/slice-1-auth in the supplied folder.

**Goal:** Real account → personal Tenant → isolated project/thread persistence → guarded Web Shell, with reproducible security checks.
**Architecture:** Cookie-backed opaque sessions, Argon2id passwords, server-resolved TenantContext; routers validate/depend on services; repositories own SQLAlchemy queries. PostgreSQL constraints enforce membership and same-tenant links. Redis limits authentication attempts. React pages consume generated DTOs through services; TanStack Query owns auth/server state.
**Spec:** prompt.md Slice 1 and root AGENTS/PRD/TECHNICAL/DESIGN; preserve reference layouts.

## Global constraints and decisions

- No keys, session tokens, CSRF values or private request bodies in logs/artifacts; .env stays ignored.
- Session cookie HttpOnly/SameSite=Lax; production requires Secure. Session/CSRF secrets stored only as hashes. Fifteen-character minimum password, max 128; no email verification/password reset claim.
- All writes require an allowed exact Origin; authenticated writes additionally require session-bound X-CSRF-Token. No browser-provided tenant_id is accepted.
- Project/thread creation requires Idempotency-Key with payload conflict detection; auth uniqueness/revocation remain DB-backed.
- Only authenticated project/thread APIs are introduced; Run schema and active-thread constraints are established without a fake executor/API.
- Six scene cards remain under the workbench input; interactive Registry integration remains Slice 2. Analysis stays explicitly disabled.

## Review focus

- Session expiry/revocation, inactive memberships and forged cookies must reject access.
- Cross-account UUID guessing and same-tenant foreign-key mismatches must fail.
- CSRF and Origin checks cover login/registration/logout and private writes; Redis failure must fail closed for login.
- Concurrent registration/duplicate create keys must not duplicate users/Tenants/projects.
- Route restoration, API outages, logout and server cache clearing must not leak the prior user's state.

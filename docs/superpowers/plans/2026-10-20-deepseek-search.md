# DeepSeek Search 原生来源接入

用户在 2026-10-20 明确替换初始 Bocha 选型：只使用 DeepSeek 官方 Search 和 DEEPSEEK3_API_KEY。模型内容使用 summary，发布时间使用 date，保留相关性、权威度并计算可解释来源指数。不延续先前尚未提交的 Bocha 自定义来源质量方案。

实施范围：搜索适配器/配置、Collector、Source/Evidence 持久化与模型检索、只读 Report/Evidence API、既有报告 UI 元数据、场景 Skill 升版、健康状态及诊断脚本。沿用 React/FastAPI/LangGraph/PostgreSQL，既有 JSONB 字段承载元数据，不新建迁移，不开放 Slice 4 Run/SSE。

执行与验收顺序：

1. RED：固定端点/密钥、summary、原生字段和错误隔离测试在旧适配器下失败（6 项），随后实现 DeepSeek 适配器。
2. 验证未知评分、查询长度、旧权限映射、无搜索结果、格式错误、并发和请求节奏；保存原生字段，排除无 summary 或相关性低于 1.5 的候选，模型证据按原生日期优先近期。
3. 真实临时 PostgreSQL 迁移后验证幂等保存、候选拒绝、数据读回、租户隔离；受控图测试验证并行分析与定向返工未退化。Fixture 仅限隔离库，不混入正常业务。
4. 升版六场景至 0.1.1，保持历史快照；同步 API/TS、前端来源展示、文档和配置；独立代码审查。
5. 执行 lint/类型/后端/前端/浏览器/迁移检查，调用真实适配器并发搜索，构建容器并确认现有服务及技能目录。所有实际结果记录在 docs/fixes/2026-10-20-deepseek-search.md。

边界与风险：搜索元数据不保证事实真实性，相关性指数不等于真值概率；无 date 的官方持续更新页面允许使用但不推断日期。单进程请求节奏不是账户级分布式限流。此次不处理此前模型 3000 Token 截断，不把搜索成功宣称为完整报告通过质量验收。历史已有租户配置若需要技能版本迁移，沿用现有显式迁移协议，不重写用户配置。
